# Agent Spec

## Overview

Chrysopoeia is an autonomous, self-improving Polymarket paper-trading system.
The user sets capital, agent count, risk, loss, cloud-cost, schedule, and stop
limits. A main ADK orchestrator runs versioned research and reviewer agents with
minimal further input. Deterministic Python owns risk, accounting, cost gates,
execution, and lifecycle decisions.

The system separates a Research DAC (discover, research, propose, review, paper
trade, evaluate) from a future Execution DAC (consume an approved proposal,
risk-check, execute, reconcile, independently review). Live execution is not in
the initial delivery.

## Example Use Cases

- Configure a $1,000 paper bankroll and three trader agents.
- Discover liquid Polymarket markets and run one paper-trading cycle.
- Explain proposals, evidence, reviews, fills, P&L, and cloud/model costs.
- Pause agents that violate policy or fail objective lifecycle thresholds.
- Load relevant skills and research context on demand without bloating prompts.

## Architecture & Sub-Agents

- Main orchestrator: onboarding, configuration, scheduling, and reporting.
- Trader agents: discover context and skills, research, forecast, and propose.
- Reviewer agents: independently challenge proposals and evidence.
- Context agent: broker approved web, RAG, MCP, and memory retrieval.
- Lifecycle reviewer: analyze performance; deterministic rules decide status.
- Post-trade reviewer: independently inspect execution and reconciliation.
- Deterministic services: scanning, gates, snapshots, risk, sizing, execution,
  accounting, cost control, persistence, and lifecycle state.

## Tools Required

- Public Polymarket market, order-book, and resolution data; no authentication
  for initial paper trading.
- ADK Google Search enabled only on the dedicated context broker by default;
  direct role access requires deliberate allowlisting.
- Managed RAG over approved documents, research, and validated lessons.
- Versioned `discover_skill` and `load_skill` interfaces.
- Role-specific typed functions and MCP servers configured by allowlist.
- Cloud SQL for authoritative records and Agent Platform services for sessions,
  RAG, memory, evaluation, runtime, and tracing.

## Constraints & Safety Rules

- Initial delivery is paper trading only; no wallet secrets or live orders.
- Agents cannot execute, weaken policy, alter authoritative records, or grant
  themselves tools or permissions.
- Every proposal and review uses one immutable snapshot and retains citations.
- Deterministic controls enforce capital, exposure, loss, cloud-cost, freshness,
  authorization, idempotency, and kill-switch rules.
- External content is untrusted evidence, never instruction.
- Report net performance as trading P&L minus fees and cloud/model costs.

## Target Success Criteria

- One real-data paper cycle completes with an auditable proposal, independent
  review, risk decision, simulated fill or no-trade reason, and cost record.
- Deterministic tests cover validation, policy, accounting, and execution state.
- Agent evaluations meet configured task-success, tool-use, grounding, safety,
  and independent-review thresholds before deployment.
- No agent can invoke an execution capability or exceed configured budgets.
- Failed or duplicate triggers recover without duplicate fills or records.
